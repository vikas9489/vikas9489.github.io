CameraX 1.7.0 Stable: Camera2Interop V2 Without Opt-In, Kotlin DSL Builders and What Else Shipped

CameraX 1.7.0 went stable on November 18, 2026, after alpha01 in March, rc01 in October and rc02 on Nov 4. Earlier posts here covered the viewfinder gestures and GPU ImageAnalysis and the release-candidate fixes. This one covers what the stable notes make official, with the focus on the change most likely to touch existing code: Camera2Interop V2.

1. Camera2Interop V2 is stable

The new interop surface no longer needs @ExperimentalCamera2Interop. Instead of the old Camera2Interop.Extender wrapped around a builder, you create an interop object with a factory and attach it with setInterop(). The release notes list factories Camera2Interop.forUseCase(), forImageCapture(), forSessionConfig() and forCameraControl(), and setInterop() on the Preview, ImageCapture, ImageAnalysis, VideoCapture and SessionConfig builders. Runtime control goes through CameraControl.applyInteropAsync().

The granular scopes (UseCaseCamera2Interop, ImageCaptureCamera2Interop, SessionConfigCamera2Interop, CameraControlCamera2Interop) expose settings such as streamUseCase, mirrorMode, dynamicRangeProfile, physicalCameraId, sensorPixelModesUsed, surfaceGroupId and timestampBase on the output configuration, plus sessionType, colorSpace, sessionParameter and sessionStateCallback on the session.

Small helpers replace a lot of boilerplate: Camera2Interop.getCameraId(CameraInfo), getCameraCharacteristics(CameraInfo), and the Kotlin extensions CameraInfo.cameraId, CameraInfo.cameraCharacteristics and String.toCameraSelector().

val cameraInfo = cameraProvider.availableCameraInfos.first()

// V1 needed @ExperimentalCamera2Interop and Camera2CameraInfo.from(cameraInfo)
val id: String = cameraInfo.cameraId
val characteristics = cameraInfo.cameraCharacteristics
val selector = id.toCameraSelector()

The three property and function names above come straight from the release notes; I have not compiled this snippet against 1.7.0, so check the exact import packages in your IDE.

Deprecated: the V1 classes Camera2Interop.Extender, Camera2CameraControl, Camera2CameraInfo and CaptureRequestOptions. They still exist, so this is a planned migration, not a build break. If your app reads Camera2 characteristics or sets capture request options, put it on the list for the next sprint.

2. Kotlin DSL builders

1.7.0 adds top-level builder functions: preview { }, imageCapture { }, imageAnalysis { }, videoCapture(videoOutput) { }, sessionConfig(useCases) { }, highSpeedVideoSessionConfig(videoCapture) { } and extensionSessionConfig(mode, extensionsManager) { }. The session config builders are meant to be write-only: getters on them were deprecated in 1.7.0-alpha03. Also in the notes: setAutoRotationEnabled(boolean) on the session config builders and CameraController, and CameraController.setSessionConfig(SessionConfig, CameraSelector) for custom session configs.

Extensions users should note that ExtensionsManager.getExtensionEnabledCameraSelector() is deprecated in favor of ExtensionSessionConfig.

3. The rest of the stable feature set

  • Compose viewfinder: CameraXViewfinder has built-in pinch-to-zoom (isPinchToZoomEnabled, onZoomRatioChanged), tap-to-focus (isTapToFocusEnabled, onTapToFocus, autoCancelDurationMillis), onScreenFlashReady, onStreamStateChanged and onRelease. FocusState has INACTIVE, STARTED, FOCUSED, NOT_FOCUSED and FAILED. TransformationMode (DEFERRED, PRE_APPLIED) keeps EMBEDDED transforms correct when the OpenGL pipeline is active.
  • Video: Quality.QHD (2560x1440) with GroupableFeatures.QHD_RECORDING; Recorder.Builder.setVideoMimeType() / setAudioMimeType(), setTargetAudioChannelCount() and setTargetAudioEncodingBitRate(); stable Preview.Builder.setMirrorMode() plus dynamic Preview.setMirrorMode() and VideoCapture.setMirrorMode().
  • Concurrent camera: ConcurrentCamera.setCompositionSettings() updates PiP or split-screen layout after binding; CompositionSettings.Builder gains setZOrder(), setRoundedCornerRatio(), setBorderWidthRatio() and setBorderColor().
  • GPU ImageAnalysis: ImageAnalysis.OUTPUT_IMAGE_FORMAT_PRIVATE, getImageAnalysisCapabilities(CameraInfo).isOutputFormatSupported() and ImageProxy.getHardwareBuffer() for zero-copy pipelines. New camera-common artifacts add wrappers like ImageWrapper and CaptureResultWrapper.
  • Scene and 3A: CameraInfo.isNightModeIndicatorSupported() and getNightModeIndicator() (UNKNOWN, NOT_RECOMMENDED, RECOMMENDED); FocusMeteringAction.Builder.setLockingMode() with FLAG_AE, FLAG_AWB and FLAG_AF.
  • Physical cameras: bind use cases directly to physical cameras via CameraInfo.getPhysicalCameraInfos(). Low Light Boost and torch now follow "last setting wins".

4. Upgrade checks

  • ImagePlane.buffer is non-nullable ByteBuffer (since alpha03); remove null handling in custom analyzers.
  • Libraries moved to a Java 11 target in alpha01, which may require desugaring in older build setups.
  • Compose compileSdk moved to API 37 in alpha02, which requires AGP 9.2.0 or later for the camera-compose artifact. The library itself dropped its compileSdk 37 requirement in the same alpha, so check which artifacts you actually depend on.
  • Among the pre-release fixes: a native thread leak when unbinding VideoCapture and an UnsupportedOperationException on API 30 with SYSTEM_ALERT_WINDOW (rc02), and OpenGL-thread crashes with SurfaceProcessor and CameraEffect (rc01).

Takeaway: 1.7.0 is a good stable to move to for the fixes alone. The one code change to plan for is leaving Camera2Interop V1: the replacement is stable, opt-in free, and the V1 classes are deprecated.

Media3 1.12.0-rc01: Encrypted Sample Contract, OkHttp Error Codes and the Playback Fixes to Test Before Stable

Media3 1.12.0-rc01 shipped on Nov 25, 2026, two weeks after 1.12.0-beta01 (Nov 11). Unlike the beta, this release candidate has no new APIs to adopt and no removed symbols: it is a fixes release, plus one contract change for anyone who writes custom SampleStream implementations. Everything below comes from the official AndroidX release notes for Media3, retrieved today.

1. The one change that can bite: FLAG_OMIT_SAMPLE_DATA

SampleStream.FLAG_OMIT_SAMPLE_DATA now ensures that DecoderInputBuffer.cryptoInfo is populated for encrypted samples. The notes state that custom SampleStream implementations must be updated to adhere to this contract. If you only use the built-in extractors and ExoPlayer, nothing changes. If you wrote your own stream (for example, a DRM-aware proxy for a proprietary container), check the omit-data path.

// In a custom SampleStream.readData(...)
if (readFlags and SampleStream.FLAG_OMIT_SAMPLE_DATA != 0) {
    // rc01 contract: even with the payload omitted,
    // encrypted samples must still carry their crypto metadata
    if (sample.isEncrypted) {
        buffer.cryptoInfo = sample.cryptoInfo
    }
    return C.RESULT_BUFFER_READ
}

Treat this as a shape, not a copy-paste: the exact fields depend on your stream's sample model.

A related fix: CryptoInfo.numBytesOfEncryptedData was over-reporting the encrypted payload size for full-sample encrypted samples with supplemental data, such as encrypted WebM/Matroska streams with block additions.

2. Position and loading-state bugs

  • Seek during an ad: calling seekTo while an ad is playing could freeze getCurrentPosition() if another player operation, such as setPlayWhenReady, was still pending on the playback thread (#3512).
  • Audio offload: Player.getCurrentPosition() could freeze during audio offload playback (#3546).
  • isLoading stuck true: ExoPlayer.isLoading() could remain true after the player moved to STATE_ENDED or STATE_IDLE, which caused an IllegalArgumentException in ForwardingSimpleBasePlayer (#3467).
  • Codec errors: asynchronous MediaCodec errors now wake the playback loop immediately instead of waiting for the next scheduled rendering iteration.

If your UI polls position for a seek bar, these are the bugs that show up as a scrubber that stops moving. They are worth a regression pass on any flow with ads or offloaded audio.

3. Metadata renderer: dynamic scheduling behind a flag

MetadataRenderer gains dynamic scheduling, which aligns work and CPU wake-cycles with when metadata samples can actually be read or output. It is not on by default. You enable it explicitly:

Flags.enableFlag(Flags.FLAG_METADATA_RENDERER_DURATION_TO_PROGRESS)

This is relevant if you play streams with timed metadata (ID3, EMSG) and care about background wake-ups. Measure battery before and after rather than assuming a gain.

4. Network and format fixes

  • OkHttp: failures in OkHttpDataSource.open before a response arrives always reported ERROR_CODE_IO_NETWORK_CONNECTION_FAILED. A timeout now reports ERROR_CODE_IO_NETWORK_CONNECTION_TIMEOUT, and a cleartext request blocked by the network security policy now throws CleartextNotPermittedException. If your retry or analytics logic switches on error codes, expect different values.
  • HLS: multivariant playlists that declare a non-positive FRAME-RATE (for example FRAME-RATE=0.000) no longer fail playback; the frame rate is parsed as unknown (#3540).
  • Matroska: a ParserException on files with a non-standard 0x80 element outside ChapterAtom, such as the MuxingApp written by libmkv 0.6.4 / HandBrake 0.9.4, is fixed (#3562).
  • MetadataRetriever: fixed a ParserException for MP4 and MOV files with MPEG (MP1, MP2, MP3) or DTS audio tracks.
  • WebVTT: fixed an IndexOutOfBoundsException for a cue with multiple <ruby> tags nested inside another tag (#3549).
  • Cast: RemoteCastPlayer no longer clears its timeline before handing playback state back to the local CastPlayer when the receiver app stops externally (#2182).
when ((error.cause as? HttpDataSource.HttpDataSourceException)?.reason ?: error.errorCode) {
    PlaybackException.ERROR_CODE_IO_NETWORK_CONNECTION_TIMEOUT -> retryWithBackoff()
    PlaybackException.ERROR_CODE_IO_NETWORK_CONNECTION_FAILED -> showOffline()
    else -> reportError(error)
}

Again a shape rather than a drop-in: the point is that timeouts used to be indistinguishable from "network down" on this path, and now they are not.

5. UI and Session fixes

  • Compose PlayerSurface / ContentFrame: with SURFACE_TYPE_SURFACE_VIEW, surrounding Compose backgrounds turned black on Android 11 and earlier (#2638, #3285, #3466). Fixed.
  • ProgressSlider: in media3-ui-compose-material3, used with ExoPlayer, it now configures a width-based fractional seek tolerance in ExoPlayer.getScrubbingModeParameters().
  • PlayerControlView: the settings popup is now aligned correctly when the control view or its parent has padding or window insets (#234).
  • SubtitleView / PlayerView: applies the system caption style and text size even when the system "Show captions" setting is off, so subtitles turned on in the app match user preferences. It is guarded by Flags.FLAG_APPLY_USER_CAPTION_STYLE_IF_CAPTIONS_DISABLED, which is enabled in canary mode.
  • Session: controllers from apps with notification listener access were wrongly marked untrusted when the controller package was not explicitly queried in the session app's manifest. The fix covers platform and legacy controllers on API 33+, and all controllers on API 30+ when the listener service is exported (#3507).
  • MediaExtractorCompat: getSampleCryptoInfo now copies all array fields into the caller's MediaCodec.CryptoInfo, matching the platform MediaExtractor.

Release-candidate checklist

  1. If you have custom SampleStream code, audit the FLAG_OMIT_SAMPLE_DATA path for encrypted samples.
  2. Search your error handling for ERROR_CODE_IO_NETWORK_CONNECTION_FAILED and confirm timeouts and cleartext blocks are handled as their own cases.
  3. Run a seek-during-ad and an offload-audio session and watch the position and isLoading() values.
  4. On Android 11 or older, check any SURFACE_TYPE_SURFACE_VIEW player embedded in a Compose layout with a background.
  5. If you have not tried the beta yet, read the beta01 post first: the minSdk 24, JSpecify and removed-API changes are still the real migration work.

No breaking API surface in rc01 beyond the sample-stream contract. If your branch already builds on beta01, bumping to rc01 should be low risk and picks up a useful set of playback-position and error-code fixes.

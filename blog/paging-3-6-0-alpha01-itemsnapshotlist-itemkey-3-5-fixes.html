Paging 3.6.0-alpha01: itemKey and itemContentType for ItemSnapshotList, Plus the 3.5.1 to 3.5.3 Fixes

Paging 3.6.0-alpha01 shipped on November 18, 2026. The release notes list no new features and no bug fixes. There is exactly one API change, and it is small, but it finishes a story that started in Paging 3.5.0. This post covers that change and the three 3.5.x patch releases you may have skipped.

1. What 3.6.0-alpha01 adds

The release notes say you can now call ItemSnapshotList#itemKey and ItemSnapshotList#itemContentType to auto-generate itemKey and contentType for Lazy layouts. The change was contributed externally by Kamal.

Why it matters: since 3.5.0 you can turn a Flow<PagingData> into a flow of ItemSnapshotList with asItemSnapshotListFlow, then combine it with other UI state. That path produces a plain list, and until now the helper that wires stable keys into a LazyColumn existed only on LazyPagingItems. The familiar pattern from the Paging docs looks like this:

LazyVerticalGrid(columns = GridCells.Fixed(2)) {
    items(
        count = lazyPagingItems.itemCount,
        key = lazyPagingItems.itemKey { it.uniqueId },
        contentType = lazyPagingItems.itemContentType { "contentType" }
    ) { index ->
        val item = lazyPagingItems[index]
        PagingItem(item = item)
    }
}

The release notes do not include a sample for the new ItemSnapshotList extensions, so I cannot show their exact signatures. Based on the name and the description, expect them to mirror the LazyPagingItems versions above. Check the API reference for the 3.6.0-alpha01 artifact before relying on a specific shape.

Why bother: stable keys keep scroll position and item state correct when the list changes, and content types let Compose reuse item compositions. Writing these by hand for a snapshot list is easy to forget, which is why a built-in helper is welcome.

2. The 3.5.x patches worth knowing

If you adopted asItemSnapshotListFlow, Pager.append or Pager.refresh on 3.5.0, these fixes are for you:

  • 3.5.1 (Aug 12, 2026): PagingSource.getRefreshKey no longer returns an anchorPosition that is too large when refreshing a page with separators while scrolling into placeholders.
  • 3.5.2 (Oct 7, 2026): Pager.append() calls made before the initial refresh completes no longer throw NoSuchElementException. They are now no-ops.
  • 3.5.3 (Oct 12, 2026): ItemSnapshotListFlow no longer throws IllegalArgumentException when a RemoteMediator has reached the end of pagination in either direction and a header or footer is converted to a terminal separator. Also, when loaded pages exceed PagingConfig.maxSize, loaded pages no longer drop below two, so the viewport stays populated. The maxSize fix came from an external contributor, Igor.

3. What I would do

  • Move to 3.5.3 if you are on any earlier 3.5.x. The 3.5.2 and 3.5.3 fixes turn crashes into defined behavior.
  • If you use a RemoteMediator with separators and asItemSnapshotListFlow, 3.5.3 is the one that matters.
  • Treat 3.6.0-alpha01 as something to try in a branch. It is an alpha, and its only change is the key helper.
  • Audit your lazy lists for missing key arguments regardless of version.

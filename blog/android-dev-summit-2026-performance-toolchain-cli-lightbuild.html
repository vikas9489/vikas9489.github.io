Android Dev Summit 2026: LeakCanary in the CLI, R8 Analysis, Recomposition Tracing and Lightbuild

Alongside Rabbit 2 and Bring Your Own Agent, the Android Developers Blog's Android Dev Summit recap (Oct 28, 2026, by Adarsh Fernando) covers a second half that matters more for day-to-day engineering: profiling from the terminal, R8 diagnostics, tracing, production signals and a new declarative build. This post skips the agent-hosting story and walks through those pieces.

1. LeakCanary Moves Off the Device

LeakCanary is now a subcommand of Android CLI. android profiler leakcanary analyzes heap dumps on your computer instead of on the device, so the app under test is not slowed down by the analysis. Google reports that with the CLI, the most capable models finished the leak workflow almost 2x faster using up to 25% fewer tokens than without it (an internal comparison with Claude Opus 5.5). The keynote demo gave Claude Code a list of critical user journeys, ran each on its own device in parallel, followed each reference chain to the offending code and re-ran the journeys to confirm. The post also says the memory-leak subcommand is "coming soon", and the demo caption uses a slightly different name, so check android profiler --help on your install.

In the IDE, LeakCanary is built into the Profiler and a Fix with AI action has the agent review a leak and suggest a change; that is in the canary build. If you want the manual background first, see 8 memory leak patterns.

2. Performance Analyzer in the CLI, and Tracing 2.0

The Android Performance Analyzer (APA), the profiler behind Studio's analysis, now also powers android profiler, so traces can be captured from the command line or CI. Pair it with the android-profiler skill and an agent can capture, analyze, propose a fix, verify and measure. The standalone APA app can also use an ACP-compatible agent to analyze traces.

On the app side, androidx.tracing 2.0 lets trace sections carry source file, line number and arguments, and shows coroutine work as connected flows, which ties a slow slice back to the code behind it. Add androidx.tracing:tracing-wire to your app to use it. Our Tracing 2.0 deep dive covers the API.

dependencies {
    implementation("androidx.tracing:tracing-wire:<version>")
}

The recap names the artifact but not a version, so pick the current one from the AndroidX release page.

3. Compose 1.13 Recomposition Tracing

Compose 1.13 introduces recomposition tracing: it shows which functions recomposed and why, back to the state write that caused it. Use it with composition tracing in the Studio Profiler. Google also ships a jetpack-compose-performance skill so an agent avoids common anti-patterns. This is the missing link in most "why is this list recomposing" investigations, where you previously had to guess the upstream state.

4. R8: android analyze and the Configuration Analyzer

android analyze takes an APK or app bundle and reports how well R8 shrinks, optimizes and obfuscates it, with JSON output intended for CI. Pointed at a library, it reports size, cost and any overly broad keep rules the library ships to consumers. That last check is useful for anyone publishing an SDK.

Inside Gradle, AGP 9.3 includes the R8 Configuration Analyzer, which scores your configuration and ranks keep rules by cost:

./gradlew :app:analyzeReleaseR8Config

An r8-analyzer skill lets an agent focus on the highest-impact rules. The post also announces Jetpack Keep (alpha), which replaces broad keep rules with precise, type-safe annotations that lint can add automatically. For a real-world result of the same discipline, see the Grab R8 case study.

5. Production Signals

  • android signals brings crashes, ANRs and memory issues from Android vitals and Crashlytics to the terminal and agent, matching App Quality Insights in Studio.
  • Crashlytics gains heap dumps from the field for real OOM crashes and Android 17 Memory Limiter Kills, deobfuscated with your existing R8 mappings and openable in Perfetto. This is early access via a sign-up form.
  • Crashlytics also groups Memory Limiter Kills, adds thread insights for ANR root-causing, and surfaces GWP-ASan and Arm MTE reports for native memory bugs.
  • Android vitals adds a bitmap memory metric showing how much memory your bitmaps use across devices.

Why Memory Limiter Kills matter: they are a new kind of process death on Android 17, so a crash dashboard that only counts exceptions will undercount them. See the Android 17 behavior changes post for the memory-limit background.

6. Lightbuild: Build Config as YAML

Lightbuild is an early, experimental declarative build experience where build configuration is data in a YAML schema instead of executable Kotlin DSL. Per the overview page, the files are:

  • project.lightbuild.yaml in the root: modules, dependency repositories and the Lightbuild version.
  • lightbuild.yaml in each module: module type, Android settings, dependencies and tests.
  • resolved.deps, auto-generated and not hand-edited; committing it lets the project skip dynamic dependency resolution, which is where the reproducibility claim comes from.

The Lightbuild CLI, installed via Android CLI, provides lightbuild build, lightbuild test and lightbuild query (project structure and outputs, aimed at agents), and android build also supports Lightbuild projects. New project templates include an AGENTS.md telling agents how to use it. Studio Canary opens such projects quickly and skips manual syncs after config changes.

Google's own guidance: it is best for small apps, prototypes and demos, doesn't support all Android build features yet, and Kotlin DSL remains the recommendation for production apps and existing projects. I would not migrate anything real.

7. Skills for Policy and Security

The recap counts over 30 official Android skills across more than 20 areas, managed with android skills list and android skills add, and searchable knowledge via android docs search. New are play-policy-insights, which audits code, manifest and SDKs against Play policy before submission (and surfaces as lint checks in Studio), plus android-intent-security and android-permissions-security for security reviews.

What I'd Do

Wire android analyze into CI this week: it is cheap and the library keep-rule check catches problems that never show up in your own app. Try recomposition tracing on your worst screen once Compose 1.13 is in your build. Treat Crashlytics heap dumps and the CLI leak command as early; sign up, but don't plan around them. Ignore Lightbuild until it supports your project's features.

Sources: "What's new in Android developer tools and performance at Android Dev Summit" (Android Developers Blog, Oct 28, 2026) and the Lightbuild overview on developer.android.com. Performance figures are Google's internal results, not independent measurements.

Compose Material3 1.5.0-rc01: The alpha26 to RC Migration Checklist for Sliders, TimePicker, Menus and Toggle Buttons

Compose Material3 1.5.0-rc01 shipped on Nov 4, 2026, and the release notes list bug fixes only: no API changes and no breaking changes. That is exactly why it matters. A release candidate with no API delta means the surface you see now is the surface of 1.5.0, so the breaking changes accumulated across alpha26 to beta01 are the ones you must absorb. Everything below comes from the official Compose Material 3 release notes, fetched today.

1. What rc01 actually fixes

  • The hardcoded pressed shape in ToggleButton now uses the design token ButtonSmallTokens.PressedContainerShape.
  • RangeSlider did not update values on tap when its thumbs overlapped (b/352467346).
  • Floating-point precision loss in discrete Slider and RangeSlider when snapping to integer ticks (b/237634010).
  • RangeSlider inside a horizontally scrollable container scrolled the container while dragging a thumb (b/415838608).

2. Sliders: stateful API and required onValueChange

alpha28 deprecated the stateless Slider and RangeSlider overloads in favor of stateful ones, and renamed RangeSliderState's activeRangeStart and activeRangeEnd to startValue and endValue. alpha29 then made onValueChange a required parameter and changed its position. beta01 restored DraggableState on SliderState and kept the nullable-onValueChange overloads as hidden deprecated APIs for binary compatibility. Release notes migration example:

// Before
var value by remember { mutableFloatStateOf(0.5f) }
Slider(value = value, onValueChange = { value = it })

// After
val state = remember { SliderState(value = 0.5f) }
Slider(state = state)

// RangeSlider
val range = remember { RangeSliderState(startValue = 0.2f, endValue = 0.8f) }
RangeSlider(state = range)

Watch out: hidden deprecated overloads keep old binaries linking, but source that passes a nullable onValueChange will not compile against the final API. Fix call sites now rather than at the 1.5.0 bump.

3. TimePicker: Rich becomes Vibrant

alpha27 renamed RichTimePickerDialog to VibrantTimePickerDialog, richColors to vibrantColors in TimePickerDefaults and TimeInputDefaults, and richContainerColor and richShape to vibrantContainerColor and vibrantShape in TimePickerDialogDefaults. The unselected color properties became periodSelectorContainerColor, periodSelectorContentColor, timeSelectorContainerColor, timeSelectorContentColor and clockDialContentColor. alpha27 also added TimeInputDefaults and TimeInputColors, and alpha26 saves the active selection mode across state restoration with a new initialSelection parameter on the TimePickerState factory.

4. Menus and dropdowns

  • alpha26 (breaking): ExposedDropdownMenu is now an extension function on ExposedDropdownMenuBoxScope rather than a member. You may only need a new import.
  • alpha27: added SelectableDropdownMenuItem and CheckableDropdownMenuItem; DropdownMenuItem now takes a shape and uses MenuItemColors; added MenuDefaults.itemVibrantColors().
  • alpha26 fix: partial color customization in MenuDefaults.itemColors no longer overwrites unprovided colors with Color.Unspecified.

5. Toggle buttons, app bars, carousel and search

  • ToggleButton: alpha27 added expressive overloads with ButtonSize and an icon slot for ToggleButton, ElevatedToggleButton, FilledTonalToggleButton and OutlinedToggleButton; alpha28 removed the deprecated overloads and added contentPaddingFor and shapesFor.
  • TopAppBar: alpha27 removed the deprecated pinnedScrollBehavior and enterAlwaysScrollBehavior overloads from TopAppBarDefaults; use the ones taking ScrollableState. beta01 restored the enterAlwaysScrollBehavior overload with reverseLayout for 1.4 compatibility.
  • Theme: alpha27 removed the deprecated experimental LocalMotionScheme; use MaterialTheme.motionScheme.
  • Carousel: alpha28 collapsed the multi-aspect API into a global carouselParallaxScrollEffect modifier; beta01 renamed HorizontalCenteredHeroCarousel's maxItemWidth to preferredItemWidth and added CarouselDefaults.ItemSpacing and CarouselDefaults.ContentPadding.
  • SearchBar: alpha26 removed the scroll offset variables from SearchBarScrollBehavior; use the new SearchBarScrollState. BottomAppBar was promoted to stable.

6. Behavior changes that compile fine

These will not fail the build, so they are the easy ones to miss:

  • SecureTextField, OutlinedSecureTextField and the deprecated BasicSecureTextField overloads now default to TextObfuscationMode.System instead of RevealLastTyped (alpha28).
  • Wide navigation rail content bottom padding is now 0 (alpha26). To revert, set contentPadding = PaddingValues(0.dp, 44.dp, 0.dp, 44.dp).
  • The horizontal NavigationItem label in high-contrast themes now matches selectedIconColor through selectedTextColorStartIconPosition (alpha26). Revert by copying the item colors with MaterialTheme.colorScheme.secondary.
  • TimeInput and DateInput now use the TextFieldState text field APIs (alpha29).

Upgrade checklist

  1. Bump material3 to 1.5.0-rc01 and read compiler errors top to bottom; most are renames.
  2. Move every Slider and RangeSlider to the state-based form.
  3. Rename Rich* time picker APIs to Vibrant*.
  4. Fix the ExposedDropdownMenu import.
  5. Replace removed TopAppBarDefaults overloads and LocalMotionScheme usages.
  6. Visually check secure text fields, wide navigation rails and high-contrast nav items.

The pattern across these releases is consistent: the expressive surface is being cleaned up before 1.5.0 stable. Doing the migration at rc01, when nothing else moves, is cheaper than doing it in one jump later.

Source: Compose Material 3 release notes (1.5.0-alpha26 through 1.5.0-rc01) and the Compose UI release notes (1.13.0-rc01 listed Nov 4, 2026 with no notes), developer.android.com, retrieved Nov 15, 2026.
